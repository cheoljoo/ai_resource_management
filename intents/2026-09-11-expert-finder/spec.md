## 채택된 접근 (2026-09-11 사용자 확정 — A+B+C 전부, 5개 데이터 소스 결합)

착수 전 `AskUserQuestion`으로 정렬한 결과, 아래 세 후보를 개별 선택하는 대신 **모두 결합**하기로
확정됐다. 상세 배경은 `intent.md`의 "2026-09-11 세션에서 사용자와 정렬 완료된 결정 사항" 참고.

**A. 로컬 git 메타데이터 확장** — `--since-days` 옵션화(완료, 기본 14일 유지) + 검증 저장소를 여러 개
합쳐 총 ~20명 규모로 확대.

**B. git + Gerrit + Jira + Confluence 결합** — 원래 안보다 범위가 넓어져, Gerrit·Jira뿐 아니라
Confluence(Collab)까지 포함한 4개 시스템 + GitHub까지 총 **5개 데이터 소스**를 결합한다.
- **접근 경로(확정)**:
  - git(사내 저장소 + GitHub 원격 저장소 포함) → 로컬 clone 기반 직접 분석(기존 `expert_finder.py`
    방식의 재구현).
  - Jira/Confluence → 별도 API 토큰 발급 없이 **이 세션에 연결된 `mcp-atlassian` MCP 도구**
    (`jira_search`, `confluence_search` 등)를 그대로 사용.
  - GitHub → 로컬에 이미 인증된 **`gh` CLI**(계정 `cheoljoo`) 사용.
  - Gerrit → 기존 `gerrit_fetch.py`의 `~/code/ccr/gerrit/global_variables.py` 자격증명 재사용, 단
    owner 필터를 동료 포함으로 확장(아래 거버넌스 항목 참고).
- 단점: 5개 시스템을 엮는 만큼 복잡도가 높고, 시스템별 데이터 포맷/기간 정의가 달라 신호 결합 방식을
  신중히 설계해야 함.

**C. "Expert Finder"를 독립 산출물로 재정리** — `developer_evaluation_metrics.md` 6.6절에서 분리해
경량 문서(`expert_finder.md`)와 전용 스크립트 세트로 구성한다.
