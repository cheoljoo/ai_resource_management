# Identifying Experts in Software Libraries and Frameworks among GitHub Users

- 저자: João Eduardo Montandon, Luciana Lourdes Silva, Marco Tulio Valente (Federal University of Minas Gerais / Federal Institute of Minas Gerais, Brazil)
- 출처/venue/연도: arXiv:1903.08113 [cs.SE], 2019 (관련 축약본은 SANER 2019에 게재)
- 링크: https://arxiv.org/abs/1903.08113 / https://arxiv.org/pdf/1903.08113

## 핵심 주장 요약
현대 소프트웨어 개발은 외부 라이브러리/프레임워크(예: React, MongoDB 드라이버, Socket.IO)에 크게 의존하지만, 기존 전문성 식별 연구(Expertise Browser 등)는 조직 내부 코드 요소에 초점을 맞췄을 뿐 이런 "제3자 컴포넌트"에 대한 전문성은 다루지 않았다. 저자들은 "라이브러리를 사용하는 클라이언트 프로젝트에 기여하다 보면 그 라이브러리 자체에 대한 전문성도 쌓인다"는 가설 아래, GitHub 공개 활동 데이터(커밋, 코드 처치량 등)만으로 세 JavaScript 라이브러리(React, MongoDB Node 드라이버, Socket.IO)의 전문가를 식별하는 지도학습/비지도학습 실험을 수행했다. 지도학습(Random Forest, SVM)은 GitHub 데이터만으로는 전문가/중급/초보자를 구분하는 정확도가 낮음(최대 F-measure 0.56)을 보였지만, 비지도 군집화 방식은 "커밋 수·코드 처치량이 높은 클러스터"에 실제 전문가가 65~75% 집중되는 것을 발견해, GitHub 메타데이터가 전문성의 "부분적 프록시(partial proxy)"로 유효함을 실증했다. 검증을 위해 자기보고 설문(ground truth) 575명 분과 LinkedIn 프로필 교차 검증도 함께 사용했다는 점에서, 자기보고를 "정답 라벨"로만 쓰고 실제 예측/스코어링은 메타데이터만으로 수행하는 하이브리드 검증 설계를 취한다.

## 주요 발견/모델
- **데이터 소스**: GitHub 공개 API — 후보 전문가별 13개 피처(대상 라이브러리를 import하는 클라이언트 파일에 대한 커밋 수, 코드 처치량(churn), 기여한 클라이언트 프로젝트 수 등). 설문/자기보고는 정답 검증(ground truth)에만 사용, 예측 입력에는 미사용.
- **지도학습 결과 한계**: Random Forest/SVM으로 초보자·중급자·전문가 3분류 시 최대 F-measure 0.56 — GitHub 활동만으로는 "공개 활동이 적은 숨은 전문가"(사내/비공개 프로젝트 경험자)를 구분하지 못하는 근본적 한계 확인.
- **비지도 군집화 결과**: React에서는 특정 클러스터의 74%가 실제 전문가, MongoDB/Socket.IO 클러스터에서는 각각 65%/75%가 전문가로 확인 — 높은 커밋 수·코드 처치량을 가진 활발한 기여자 군집이 전문가와 상당히 겹침.
- **결론**: GitHub 메타데이터는 전문성의 "완전한 지표"가 아니라 "부분적 프록시"이며, 낮은 피처값을 가진 사람은 전문가일 수도 초보자일 수도 있어 판별 불가 — 반대로 높은 피처값 군집은 전문가일 확률이 유의미하게 높다는 비대칭적 신뢰도를 가진다.

## 이 프로젝트에 적용한다면 (상세)
- **6.3 활동 폭/다양성 확장 (GitHub 연계)**: 현재 6.3은 "저장소/기술 스택 다양성"만 다루는데, 이 논문의 피처 설계(대상 라이브러리를 import하는 파일에 대한 커밋 수·코드 처치량·클라이언트 프로젝트 수)를 그대로 가져와 "특정 프레임워크/오픈소스 라이브러리에 대한 심화 전문성 점수"라는 세부 지표를 6.3에 추가할 수 있다. 예: 사내 프로젝트가 의존하는 특정 오픈소스 라이브러리에 대해 개인이 해당 라이브러리의 소스/이슈/PR에 직접 기여한 이력이 있는지를 GitHub API로 집계.
- **1.4 복잡도 대비 결함 밀도 및 4.1 선행 검증**: 이 논문의 비지도 군집화 방법론(고활동 클러스터=전문가 확률 높음)을 응용해, 사내 Gerrit/GitLab 데이터에서도 "복잡도 대비 결함 밀도가 낮으면서 특정 모듈 커밋 처치량이 높은 클러스터"를 찾아내는 방식으로 4.1(선행 검증 능력)을 순수 군집화 기반 지표로 보강할 수 있다 — 단, 이 논문처럼 지도학습(3분류 정확도)의 한계를 명시하고 "높은 값=전문가 가능성 높음"이라는 단방향 해석만 채택해야 한다.
- **핵심 주의점(한계 반영)**: 이 논문 자체가 "낮은 GitHub 활동 = 초보자"라는 역방향 추론이 성립하지 않음을 실증했으므로(F-measure 0.56에 그친 이유), `developer_evaluation_metrics.md`의 모든 메타데이터 기반 `[O]`/`[△]` 지표에 대해 "값이 낮다고 해서 곧 역량 부족을 의미하지 않는다"는 경고 문구를 1.3절 안티패턴 표 또는 각 소항목 "보완/주의점"란에 추가로 명시할 근거가 된다. 특히 사내 시스템 접근 권한이 적은 신규 입사자나, 비공개/레거시 시스템 위주로 일하는 개발자에게 이 비대칭성이 왜곡을 유발할 수 있다.
