# AI Flywheel 2단계 — 유스케이스 포트폴리오 비교 (2026-09-11)

PwC GenAI Flywheel 보고서(6쪽)의 **7대 평가 기준**으로, 이 프로젝트(AGILEDEV-1118: 개발자 진단
프로필 + 인정/경고 신호 + Expert Finder)의 투자 타당성을 다른 후보 유스케이스와 비교한다. 목적은
"지금 하고 있는 일이 계속 투자할 가치가 있는가, 아니면 다른 곳에 자원을 돌리는 게 나은가"를 판단하는
것 — plan.md의 "AI Flywheel 관점 진단" 절 2단계 항목 이행.

**평가 기준**: 마진(매출·비용) 영향 / 사업 모델 영향 / 운영 모델 영향 / 경쟁 환경 영향 / AI 모델
타당성 / 변화의 원동력 / Responsible AI 견지 가능 여부. 상/중/하 척도는 절대 비교가 아니라 세
후보끼리의 **상대 비교**다.

## 후보 1 (현재 진행 중): 개발자 진단 프로필 + 인정/경고 신호 + Expert Finder

| 기준 | 평가 | 근거 |
| :--- | :---: | :--- |
| 마진 영향 | 하~중 | 직접 매출/비용 절감이 아니라 이직률 감소·병목 조기 해소 같은 간접 효과 — 정량화 어려움 |
| 사업 모델 영향 | 하 | 제품/서비스가 아니라 내부 관리 프로세스 개선용 |
| 운영 모델 영향 | 중 | 매니저 1:1 대화를 트리거하는 정도로 국한(자동 조치 없음, 1.6절) |
| 경쟁 환경 영향 | 하 | 사내 도구라 외부 경쟁 우위 요소 아님 |
| AI 모델 타당성 | 상 | 순수 결정론적 Python 스크립트(LLM 추론 없음) — 재현 가능하고 검증하기 쉬움. 다만 의미 분석은 못 함(SMILE과의 gap, 이전 대화 참고) |
| 변화의 원동력 | 중 | 원 티켓(경영진 요구)에서 시작된 하향식 니즈 — 실제 매니저 사용자의 채택 검증은 아직 안 됨 |
| Responsible AI 견지 | 상 | 이 프로젝트에서 가장 두텁게 구현된 축(1.2~1.7절, 7장) |

**종합**: 재무적 가치는 낮지만 **구현 비용이 사실상 0에 가깝고(로컬 git 스크립트만)** Responsible AI
리스크 관리가 매우 뛰어나다 — "저비용·저위험·저~중 가치"의 안전한 투자.

## 후보 2: Jira 티켓 트리아지/중복 탐지 어시스턴트 (미착수, 비교용 가상 후보)

| 기준 | 평가 | 근거 |
| :--- | :---: | :--- |
| 마진 영향 | 중 | 티켓 처리 시간 단축 → 리드타임 감소로 이어질 가능성 |
| 사업 모델 영향 | 하 | |
| 운영 모델 영향 | 상 | 모든 개발자·매니저가 매일 쓰는 Jira 워크플로에 직접 개입 |
| 경쟁 환경 영향 | 하 | |
| AI 모델 타당성 | 중 | 유사 티켓 탐지는 임베딩/검색 기반 성숙 기술이나, 실제 정확도는 검증 필요 |
| 변화의 원동력 | 상 | 실사용자가 일상적으로 쓰는 도구라 채택 저항이 낮음 |
| Responsible AI 견지 | 상 | 개인 평가와 무관, 데이터도 이미 업무상 공개된 Jira 내용 |

**종합**: 후보 1보다 **운영 모델 영향과 채택 가능성이 높을 수 있는 미착수 유스케이스** — 별도 신규
유스케이스로 고려할 가치가 있으나 이번 intent 범위는 아니다.

## 후보 3: Gerrit 코드 리뷰 보조 — "신규 콘텐츠 생성" 패턴(33%, 6대 패턴 중 최고 가치)

| 기준 | 평가 | 근거 |
| :--- | :---: | :--- |
| 마진 영향 | 상 | 6대 패턴 중 가치 비중이 가장 높은 패턴에 해당(company-practices/pwc-genai-flywheel.md 참고) |
| AI 모델 타당성 | **하** | **SMILE이 이미 동일 기능(Code Review Critical/Warning/Info 등급)을 상시 제공 중** — 직접 만들면 중복 투자 |
| Responsible AI 견지 | 중 | 자동 리뷰가 사람 리뷰를 대체하는 방향으로 오용될 위험(품질·책임 소재 이슈) |

**종합**: 가치는 가장 높지만 **SMILE과 완전히 중복**된다 — 직접 구현보다 SMILE 활용(plan.md 5단계)에
투자하는 것이 압도적으로 효율적. 이 비교 자체가 "5단계(SMILE 고유 데이터 차별화)"의 우선순위를
뒷받침하는 근거가 된다.

## 결론 및 추천

1. **현재 프로젝트(AGILEDEV-1118)는 계속 유지할 가치가 있다** — 이미 완료됐고 추가 투자 부담이
   거의 없는 "저비용·저위험" 자산이기 때문이다. 적극적으로 더 파고들 필요는 없지만 폐기할 이유도
   없다.
2. **추가로 새 자원을 투입한다면, 이 프로젝트를 더 키우기보다 다음 두 곳이 우선순위가 높다**:
   - **SMILE 프로젝트 등록**(plan.md 5단계) — 후보 3 비교에서 드러났듯, 코드 리뷰·요구사항 추적
     같은 고가치 영역은 이미 SMILE이 풀고 있으므로 새로 만들기보다 등록·연동이 훨씬 효율적.
   - **Jira 트리아지 어시스턴트**(후보 2) — 원 티켓과는 무관한 새 유스케이스이지만, 운영 모델 영향과
     실사용자 채택 가능성이 이 프로젝트보다 높다.
3. 이 결론은 plan.md의 2단계 백로그를 이행 완료로 표시하는 근거다.
